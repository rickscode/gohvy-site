If you have decided to train the Heavy Duty way — one set to failure, few sessions, real recovery — the next practical question is what to log it with. Search for a heavy duty training app and you will find two camps: general-purpose workout trackers with a Mentzer template bolted on, and a small number of apps built around high-intensity training from the ground up. The difference matters more than it looks, because Heavy Duty is a method with rules, and a logger that does not enforce the rules leaves you running the method from memory — which is exactly how it fails.

## What the method actually demands from software

Heavy Duty is not just "fewer sets". It is a closed loop: perform, log, progress, recover, repeat. (New to the method itself? Start with [What Is Heavy Duty Training?](/insights/what-is-heavy-duty-training) and [Mike Mentzer's Heavy Duty Workout, Explained](/insights/mike-mentzer-heavy-duty-workout).) A tool that supports it has to close that loop:

**1. Progression must be calculated, not remembered.** The entire engine of the method is progressive overload on a single working set. That means every exercise needs a target weight that moves according to rules: add weight after a strong set, hold while the muscle catches up, deload when you stall hard. In GOHVY's implementation: 8+ reps at failure and the weight goes up next session; 4-7 and you hold; 3 or fewer triggers a 10% deload. A generic tracker will happily record whatever you type, forever. That is a diary, not a coach.

**2. Recovery must be enforced, not suggested.** The set sends the growth signal; the days after it do the building. A Heavy Duty app should actively stop you from training again too soon — a rest lock, not a gentle reminder. Any app whose streak features reward you for showing up daily is optimizing for the opposite of this method.

**3. The working set must be unambiguous.** One set to failure means the app should know which set is *the* set — prescribe the warm-ups, then treat the heavy duty set as the event that gets logged, judged, and used for the next session's math. If every set is just a row in a table, the method's structure evaporates. The reasoning behind the single set is covered in [Why One Set to Failure Beats Endless Volume](/insights/one-set-to-failure).

**4. It must survive a real gym session.** Failure training happens with shaking hands, between machine swaps, around phone calls. The app has to handle a mid-workout interruption without losing your logged sets, let you swap equipment while keeping each machine's own progression history, and work offline-ish at the rack. This sounds mundane. It is the difference between logging and rebuilding a workout from memory in the car park.

## Where generic trackers fall short

Popular general trackers — the Hevys and Strongs of the world — are excellent diaries, and for volume-style programs a diary is genuinely enough. But run Heavy Duty on one and you become the engine: you decide the weight jumps, you interpret stalls, you police your own rest days, you resist the app's implicit pressure to add sets and sessions because the interface makes adding things easy. Every one of those decisions is a place where the method silently degrades. Mentzer's own clients had him standing over the logbook making those calls. A diary hands them all back to you.

Template marketplaces (a Mentzer routine inside a general app) fix the exercise list but nothing else: progression, failure standards, and recovery all remain manual.

## The honest checklist

Whatever app you evaluate — including ours — ask:

- Does it **calculate my next working weight** from my logged reps, per exercise?
- Does it **enforce rest** between sessions, or just schedule things?
- Does it distinguish **warm-ups from the working set**, with failure assumed on the working set?
- Does it keep **separate progression per equipment variant** (barbell squat vs. leg press are different lifts with different loads)?
- Does it survive **interruptions mid-workout** without losing sets?
- Can it explain **why** it prescribed a weight — deload, hold, or increase?

If the answer to the first two is no, you are looking at a diary. Nothing wrong with diaries — but the method's results come from the rules, and someone has to run them.
